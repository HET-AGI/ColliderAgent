# Reproduction Guide Generator

Creates `reproduction/` for one run. Everything inside is self-contained: nothing at rest points outside the directory, and `run_all.sh` recreates the standard pipeline layout under `reproduction/workdir/` at run time.

## Which run and what to read

Read `progress/run_manifest.yaml` (the named run; else the only run; else the most recent). Then read that run's `stepN_*.json` sidecars for paths, run names, cross sections, and parameters, the `stepN_*.md` files, and the original task file. Physics facts come from the scripts and sidecars, never from paraphrase.

## Package layout

```
reproduction/
├── README.md                  # the guide (in the user's language; code comments in English)
├── run_all.sh                 # --magnus (default) | --local, plus --from-fr
├── models/<Model>.fr
├── models/<Model>_UFO/        # the UFO that was generated and validated in the run (cp, never regenerate silently)
└── scripts/                   # cp of scripts/*.mg5, scripts/*.ma5, scripts/*.py, analysis/*.py
    └── generate_ufo.wl        # new: WolframScript for local --from-fr
```

Copy first, then fix: `cp` every script and the UFO directory, then grep the copies for absolute paths (`/home/`, `/Users/`, `/tmp/`) and edit only the offending lines to relative equivalents (`os.path.join(SCRIPT_DIR, …)`). Pipeline scripts are written with relative paths, so most copies need no change. Never alter physics content: Lagrangian terms, couplings, processes, scan ranges, cuts, plot styles.

## run_all.sh

Bash with `set -e`; parses `--magnus`/`--local` and `--from-fr`; `SCRIPT_DIR`, `WORK_DIR=$SCRIPT_DIR/workdir`, `MG5_BIN`, `FR_PATH` overridable by environment; creates `workdir/{models,events,output/figures,output/data}`; each step skips when its output exists; prints a header per step with the backend name.

| Step | Magnus backend | Local backend |
|---|---|---|
| 1 UFO | default: `cp -r models/<Model>_UFO workdir/models/`; with `--from-fr`: `magnus run validate-feynrules …` then `magnus run generate-ufo … --output workdir/models/<Model>_UFO` | default: same `cp`; with `--from-fr`: `cd workdir && wolframscript ../scripts/generate_ufo.wl` |
| 2 Events | `magnus run madgraph-compile -- --ufo … --process "…" --output workdir/events/<label>` then `magnus run madgraph-launch -- --process … --commands "…" --output …` with the exact launch body from the run | `cd workdir && $MG5_BIN ../scripts/mg5_<label>.mg5` |
| 3 MA5 (if used) | `magnus run madanalysis-process …` | `ma5 ../scripts/ma5_<label>.ma5` |
| 4 Plots | `python3 scripts/plot_*.py` (same on both) | same |

The two backends set parameters differently, and the script must use each backend's syntax: local MG5 scripts say `set MZp 1000` / `set WZp Auto` / `set MZp scan:[…]`, while the Magnus launch body says `set param_card MASS 9000001 1000` / `set param_card DECAY 9000001 Auto` / `set param_card MASS 9000001 scan:[…]` between exactly two `done` lines (madgraph-simulator skill). Add `set use_syst False` on Magnus unless the run used systematics.

## README.md

1. Overview: physics goal, run label, pipeline diagram, backend table.
2. Prerequisites: Python + numpy/matplotlib for both; local needs MadGraph5 (and Mathematica + FeynRules only with `--from-fr`); Magnus needs `pip install magnus-sdk` and `magnus login`.
3. File inventory with backend-specific files marked.
4. Automated run: the default (shipped UFO) and `--from-fr` modes, what each step does, where outputs land, and a note that `run_all.sh` was generated by ColliderAgent — each step was verified in the run, the end-to-end script was not.
5. Step-by-step instructions: per step, purpose, input files, the local and the Magnus commands, key parameters, how to verify, expected outputs.
6. Expected results: the run's key numbers (cross sections per point, fit results) with a note on MC statistical uncertainty.
7. Notes: PDF sets and the `--pdf` flag, the two-`done` launch body, runtime estimates, physics caveats.

Finish by listing `reproduction/` and confirming that no absolute path remains in the copied scripts.
