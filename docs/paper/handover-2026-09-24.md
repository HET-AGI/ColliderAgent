## 4. 运行注意事项（都已写进 skills 或 harness，但补跑时请知晓）

1. 无头模式必须 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`（harness 已设），否则子 agent 超过 10 分钟会被杀。
2. `claude -p` 的 `usage` 只算主会话，tokens 要用 `metrics.json` 里的 `tokens_in_total`（含子 agent）。
3. Delphes launch：每个 job ≤3 个 10k run，或用 `!` 清理；不要把 9 个 run 放一个 launch。
4. Opus 4.6 有 1/9 的概率不触发 orchestrator（MuC Fig. 11 那次自己在主会话跑完，子 agent 调用 0 次，结果正确）。
5. 在同一台机器的后台 Bash 里直接起 `claude -p` 可能报 "Not logged in"；用 `run_benchmark.sh`（setsid nohup）启动就没问题。
6. 每个沙盒的 `.claude-config/agent-memory/` 里有子 agent 写的 lesson，跑完用 `python3 scripts/memory/distill.py import --from <sandbox>/.claude-config/agent-memory` 并入中央库；目前中央库 28 条，其中 2 条已在 2 次独立 run 里重复出现（并行 launch 的 run_name 冲突；默认值等于请求值时无法察觉 set 行被吞）。

## 8. 分支与总报告（2026-09-26 晚）

- 三套编码 agent 各有一个分支：`main` / `feat/skill-evolution-v2`（Claude Code：`src/skills` + `src/agents`，`memory: user`）、`codex-com`（Codex：`.agents/skills` + `.codex/agents/*.toml` + `AGENTS.md`）、**`gemini-com`**（Gemini CLI：同一份 `.agents/skills` + `.gemini/agents/*.md` 四个本地子 agent + `GEMINI.md`）。`run_benchmark_gemini.sh` 默认从 `../ColliderAgent-gemini` 取 GEMINI.md 与子 agent；`--no-subagents` 复现 9/26 的 skills‑only 对照。
